01

销售辅助系统

自用中 · 每天跑

把客户资料、方案、报价、跟进节奏，收敛成一条能跑的流水线。

为什么做

客户是高校和科研院所，一个单从第一次接触到签约要跟三四个月，中间散落着论文方向、预算周期、设备清单、谁答应过什么。表格管到第 11 个客户就崩了 —— 不是信息不够，是信息之间没有关系。

我要的是：早上打开就知道今天该找谁、该说什么、上次承诺的什么还没兑现。

怎么做
  • 数据层：客户档案 / 沟通记录 / 方案版本，三层各自结构化，靠客户 ID 串起来。
  • 判断层：让模型读最近三次沟通，只输出「下一步动作 + 风险点」，不给分数。
  • 执行层：每天早上定时跑一遍，出一份简报，直接变成当天待办。
效果
$ flow
客户档案 + 沟通记录 + 方案版本 → 判断层 → 早报 → 待办

02

N1 备考教练

自用中 · 每天跑

按考试日倒排，每天该背什么、错在哪一类，不再靠感觉。

为什么做

日语 N1 是我自己给自己的硬指标，但下班之后只剩一小时。之前的问题是：每天打开书先花二十分钟决定学什么，学完也说不清哪里真的弱。

「今天学什么」这件事，我不想再每天决策一次。

怎么做
  • 倒排：从考试日往回推，把词汇 / 语法 / 阅读 / 听力拆成每日份额。
  • 错题：按错误类型归因（词义混淆 / 语法接续 / 长句断句），而不是按题号记流水。
  • 复盘：每周问一次「这周你哪里在假装努力」，答案来自实际完成率，不来自感觉。
效果
$ flow
考试日 → 每日份额 → 今日清单 → 错题归因 → 周复盘

03

每周复盘系统

自用中 · 每周跑

自动抓一周的动作，逼出一个结论。

为什么做

周末写复盘最容易写成流水账：做了 A、做了 B、推进了 C。流水账没有判断，等于没复盘。

我要的不是记录，是一个必须回答的问题：这周到底发生了什么变化？

怎么做
  • 收集：日历、账目、持仓、任务记录，先把一周的动作归集成事实。
  • 提问：把事实交给模型，只让它问问题，不给评价。
  • 收敛：逼出一句结论 + 下周一个动作。写不出来，就说明这周没干活。
效果
$ flow
日历 / 账目 / 持仓 → 归集成事实 → 只提问 → 一句结论

04

Personal AI

在用 · 持续改

让模型记住我是谁，而不是每次重新自我介绍。

为什么做

每开一个新对话，我都要重讲一遍背景：在做什么、讨厌什么、上次决定了什么。重复的部分占掉一半的上下文，也占掉一半的耐心。

我想要的是一份能被我改、能被模型读的「关于我」。

怎么做
  • 分层：事实层（经历 / 数据）与偏好层（口味 / 判断习惯）分开写，谁的错谁改。
  • 注入：按任务类型挑相关片段，不把整包塞进上下文。
  • 纠错：模型说错了，就把正确版本回写事实层，下次不再犯同一个错。
效果
$ flow
事实层 + 偏好层 → 挑片段 → 注入上下文 → 答错回写

05

简历工坊

自用 · 按需跑

事实只写一次，按岗位派生版本。

为什么做

投不同岗位要改不同简历，改到第三版就开始前后不一致：一处写 307 万，一处写 300 万；这里说 8 台，那里说 10 台。

不是不认真，是没有单一事实源。

怎么做
  • 事实分层：数字、口径、可讲范围先单独存一份，正文只引用，不改写。
  • 派生：母版 + 一份岗位描述，生成对应版本，人只负责改判断。
  • 门禁：出片前跑九项检查：一页、字号、孤字、链接可达、数字一致。
效果
$ flow
resume.yaml → 按 JD 派生 → HTML → PDF → 九项门禁

06

外卖吃啥

自用 · 偶尔卡住

把「今天吃什么」从十分钟的拉扯，压成一次点击。

为什么做

每天要做的选择里，午饭最难 —— 不是没得选，是选完还后悔。刷二十分钟，最后还是点回那家。

同事先做了一个，我拿过来改：他的口味不是我的口味，我要的是「不用想，直接出」。

怎么做
  • 画像：把常点的十几家写死，按辣度 / 价位 / 距离打标签，不爬平台。
  • 收敛：默认给一个，连点两次「不吃」才换，避免又滑回无限翻。
  • 记录：吃完顺手记一句，难吃的下一轮自动降权。
效果
$ flow
口味 / 价格 / 距离 → 今天吃这个 → 不满意换一批

07

模型斩杀线

在线 · 持续更新

把「该用哪个模型」从看完评测就下结论，变成一张能查的帕累托图。

为什么做

每家都发榜，每家都在自证第一。评测口径还不统一：推理档位、上下文长度、是否经中转 —— 比出来的往往不是能力，是配置。

所以反过来问：给定我手上的任务，哪个模型在「够聪明」的前提下最快、最便宜？

怎么做
  • 采集：70 条配置 / 34 个模型，六个纵轴可切 —— 首答案延迟、端到端耗时、输出速度、首字延迟、折价、任务耗时。
  • 判据：画帕累托前沿。线外的点都能被线上某个模型「不弱于它、且某一项更好」地替代，也就是该被淘汰的。
  • 读法：按体感优先级排序，从「首答案延迟」开始看，而不是从跑分开始。
效果
$ flow
70 条配置 → 六轴指标 → 帕累托前沿 → 线上才是候选
